Agent-assisted diagnosis: architecture and first run

A scheduled cycle that measures a candidate edshield, labels its misses with a batch model call, lets a bounded agent propose rule-level fixes, re-scores them independently, and hands a pull request to a human. Model calls run on the Claude Platform; an orchestrator script holds the secrets and the ledger; a sandbox runs the inference. The first figure is the system; the later ones are its first run on 2026-10-15.

Who did what

Claude Code cloud sessionBuilt requests, polled batches, validated answers in code, drove the sessions, streamed and committed every event, ran the path check. Every API call goes through one client pinned to the official base URL. Could not run edshield inference: all Hugging Face hosts are blocked here.
Message BatchesPlanting (Sonnet 5.5): wrote the words around each planted identifier. Diagnosis (Opus 5.5): a cause label per miss. Both at batch price, both logged request by request.
Managed Agents loopOpus 5.5 read the diagnosis and failure tables, edited rules.py, ran the fixed evaluation, decided keep / revert / stop. Capped at $30 by the platform; stopped itself at $3.77.
Sandbox containerExecuted the agent's bash and file calls: clones, model download from hf.co, CPU inference over both views and the control. A second, fresh container re-scored the final patch independently.
